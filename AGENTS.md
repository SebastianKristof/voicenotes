# Development Principles

## Modular Structure
- Keep files small and focused (maximum 600 lines per file)
- Each file should have a single, clear responsibility
- Prefer multiple small files over large monolithic files
- Group related functionality in appropriately named directories

## Session Workflow
- One task per development session
- Follow the cycle: task definition → implementation → testing → pushing
- Break down larger features into small, manageable tasks
- Complete each task fully before moving to the next

## Best Practices
- Write tests alongside implementation
- Push changes frequently after completing small tasks
- Keep commits focused and descriptive
- Regular refactoring to maintain code quality
